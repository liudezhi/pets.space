# 运行与百年保存

栖光谷以一百年为存续目标。当前可验证的交付包括运行服务、持久保存档案、生成数据库快照，以及在另一处空目录恢复。一次成功演练只证明该版本和该组测试数据可恢复。

## 服务配置

使用 Node.js 24 LTS 或 22.13 以上版本。先在仓库根目录运行 `npm ci`、`npm test`、`npm run build`，再用 `npm start` 启动构建版。Node 进程同时提供网页和档案、图片、订单 API，运维应给同一份数据配置同一个受控服务入口。以下配置由服务进程读取。

| 设置 | 用途 |
| --- | --- |
| `PETS_DATA_DIR` | SQLite 专用数据目录，必须位于仓库之外。默认在仓库同级的 `.pets-space-data/<项目目录名>/`。保存内容包含私密照片、纪念文字、权限和订单，按服务账号限权。 |
| `HOST`、`PORT` | 构建版默认监听 `127.0.0.1:4173`。公开运行时使用 HTTPS 反向代理，保留原始 Host，并由可信代理设置正确的协议转发头。 |
| `PETS_PAYMENT_MODE` | 默认 `sandbox` 为本地模拟。可选 `stripe-test` 与 `stripe-live` 分别对应 Stripe 测试和生产。配置错误时检查启动报错，修正后重启。 |
| `PETS_INVITE_CODE` | 可选的服务端邀请码。沙盒未指定时，在指定数据目录建立或复用 `sandbox-invite.txt`，控制台只给文件位置。Stripe 托管收银台可通过批量签发工具分发单用邀请。 |
| `PETS_STRIPE_SECRET_KEY` | 托管支付的商户服务端密钥，须匹配当前测试或生产模式。通过运行时密钥管理注入。 |
| `PETS_STRIPE_WEBHOOK_SECRET` | 对应模式、对应通知端点的签名密钥。换域名、换测试/生产环境时检查该端点配置。 |
| `PETS_PUBLIC_ORIGIN` | 托管付款成功和取消后返回的同源 HTTPS 站点，只填协议和主机，可带端口，不带业务路径、查询参数或锚点。 |

配置正式托管时，由运营方提供域名、持久磁盘、TLS、进程重启、监控及独立备份。Vite 开发服务供本机开发使用。调试日志、数据库目录、邀请码明文和商户密钥应由运营方单独保管。

## 可选的托管收银台

1. 先准备 Stripe **测试**商户和可接受回调的 HTTPS 站点，选择 `stripe-test`，填入该模式的三个 Stripe/源站配置。服务端创建以人民币结算的卡付款订单，请先在商户侧确认相应能力及退款责任人。
2. 在相同模式的 Stripe 管理端登记 `POST /api/payments/stripe/webhook`，订阅 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.expired`。代理需保留请求体原始字节与 `Stripe-Signature` 头；服务进程使用准确的系统时间校验签名。服务端出站访问 `api.stripe.com`，用户浏览器前往 `checkout.stripe.com`。
3. 买家在原浏览器建立订单，核对页面显示的测试或正式模式后，前往托管收银台。成功或取消时页面返回本站查询。仅在服务端核验签名、环境、金额、币种和订单匹配后发放权益。未确认的订单可从同一浏览器再次查询或继续；重复回调与重复领取按同一订单处理。
4. 已收到款项而无法履约时（例如花园改为私密或关闭收礼），订单显示需人工核对。经营方凭订单号与 Stripe 交易记录对账，在商户侧处理退款并留存处置记录。当前代码未接管自动退款或争议处理。
5. 本次验收使用独立 HTTP 测试桩和模拟签名事件。正式切换到 `stripe-live` 前，由实际商户完成测试联网验收、权限与条款审核、通知重试和异常对账演练，再注入生产配置并重启。测试与生产使用各自的数据目录、密钥和邀请码。

### 批量发放基础建园邀请码

沙盒共享码适用于本地验收。托管模式可在服务运行期间签发单用邀请码，工具与服务须指向同一实际数据目录。发放方须使用当前系统用户持有的专用私有目录，权限 0700，路径避免符号链接，明文名单只能写入新文件。以下为 POSIX 下的测试模式示例，先将变量明确指定到仓库外的受控绝对路径。

```sh
node server/issue-invites.mjs --help
install -d -m 700 "${INVITE_PARENT:?请设置专用私有目录}"
PETS_DATA_DIR="${PETS_DATA_DIR:?请设置网站正在使用的数据目录}" \
  node server/issue-invites.mjs --mode stripe-test --count 10 --output "$INVITE_PARENT/batch-001.txt"
```

每批 1 至 1000 个。输出文件权限 0600，每行一个由 32 字节随机数生成的邀请码，终端只显示数量和位置。服务数据库存储 SHA-256 摘要。码没有自动到期日，首次基础下单后预留给该购买会话；确认付款后不能再次建园。测试批次只能用于 `stripe-test`，生产需根据实际授权另行签发 `stripe-live` 批次。新增批次即时生效。将每个码私下交给对应家庭，记录批号和发放状态；后续批次使用新文件名。

## 两种留存方式

园主可导出自己的离线纪念册，在另一台设备上阅读和核对照片、名字与文字。运营方需要保存整个园区的数据库，包括私密资料、媒体、公开权限、花束和账号凭证摘要。整库备份仅交给有授权的保管人，放入受控存储。建园封面以展示版 WebP 保存。选择「同时私密保存原始照片」后，符合大小限制的原件随建园存档；主人也能在「家庭相册」添加原件。已存原件随离线纪念册导出，可按 SHA-256 核对原始字节。原件可能含拍摄位置等元数据，交接时应确认接收人的家属权限及保存范围。

## 制作和恢复一次快照

在 Linux 或支持 POSIX 目录原子重命名的本地文件系统，进入仓库根目录，使用项目声明的 Node 版本。命令中的环境变量指向运维自行创建、限权且位于仓库外部的路径。两个输出目录的父目录应已存在。为每一次快照选择新的名称。

```sh
node server/archive-store.mjs backup "${PETS_DATA_DIR:?请设置实际服务数据目录}" "${BACKUP_PARENT:?请设置备份父目录}/snapshot-001"
node server/archive-store.mjs restore "$BACKUP_PARENT/snapshot-001" "${RESTORE_PARENT:?请设置独立恢复父目录}/drill-001"
```

备份命令使用 SQLite 在线快照读取已经提交的数据，覆盖 WAL 中尚未合入主文件的记录。输出包含 `memorials.sqlite` 与 `manifest.json`。清单记录格式版本、数据库版本、时间、字节数和 SHA-256。数据库文件使用 0600 权限，目录使用 0700 权限。快照只复制数据库，命令输出完成状态。托管邀请码摘要、已付款与待处理的订单跟随数据库快照。沙盒邀请码文件、批次邀请码明文、环境凭证、域名账号和部署密钥由运营方分别托管。大库快照时预留磁盘余量，并观察磁盘使用量与写入延迟。

恢复命令核对清单版本、文件长度、校验值、SQLite 完整性、外键和核心数据表，在同一文件系统中先验证临时副本，再原子发布到新的或空的目标目录。遇到已占用目录会退出。保留正在使用的数据目录和现场副本。备份清单与数据来自同一保管方，校验和适合发现意外损坏；跨机构移交还需通过独立可信渠道核对清单或签名。

## 断开原服务，验证能否接手

1. 保存软件提交号、运行版本、锁文件、构建所需资产和备份编号。记录数据截至时间和演练负责人。确认加密介质和解密授权能由指定接任者取得。
2. 在独立试验机恢复快照。从对应提交构建服务，令 `PETS_DATA_DIR` 指向恢复目录，通过本机地址打开。演练期间使用隔离入口和沙盒，避免触发真实付款或通知。
3. 使用经同意或虚构的测试家庭核对旧分享地址、园主身份、照片、原文、地点和献花数量。分别用匿名浏览器与园主浏览器访问私密档案和图片。恢复到较早时间点时，用后续删除、转私密以及恢复码轮换的记录进行对账，完成后才重新开放访问。
4. 将个人纪念册复制到另一台断网设备，用浏览器查看。记录实际恢复耗时、可接受的数据时间差、失败原因、修正结果及复验日期。只在演练记录中使用测试编号、计数和校验摘要。
5. 真正切换服务时协调停写、核对最后一次快照、安排回退窗口。通过域名或反向代理切换到验证过的数据目录和版本，再由人检查原链接。记录交接人与生效时间。

## 建议的运营节奏

| 周期 | 责任角色 | 可留存的证据 |
| --- | --- | --- |
| 每日及重要迁移前 | 服务运维 | 自动生成快照、校验成功、加密异地副本的编号及告警。按实测数据量确定保留期、存储费和传输费。 |
| 每季 | 档案保管人与独立复核人 | 从一份随机历史快照恢复；实测一份已公开、一份私密和一份已撤回的档案，以及一份离线纪念册。 |
| 每年与负责人变更时 | 运营责任主体 | 域名与证书续期测试、独立通知渠道、密钥接续、经费审查、运营终止演练和家属联络安排。 |

可将每日副本保留 30 天、月末副本保留 12 个月作为初始预算假设，再依合同中的删除周期和恢复目标调整。定期清理过期副本，在隔离存放期间限制读取，恢复后重新应用删除和撤回记录。长期留存的纪念正文与短期灾备快照分别管理。

这些周期属于待运营方落实的策略。仓库提供手工命令与测试；异地存储、调度、告警、自动续费和责任人值班需要在实际托管环境配置并留下运行证据。

## 收费上线前的承诺

| 事项 | 由谁确定与执行 |
| --- | --- |
| 百年从何时算起，涵盖档案、照片、礼物记录与 3D 服务的哪些部分 | 明确法人或其他责任主体及实际管辖地，由专业人员复核合同、隐私、删除、继承与终止条款；向园主提供可保存的条款版本。 |
| 网站由谁长期支付费用 | 运营责任人测算每户百年存储、带宽、维护与迁移成本，明确资金来源、储备方式、审查频率和无人续任时的转托规则。 |
| 域名与机构如何接续 | 指定主责人和接任人，托管注册商、DNS、证书、独立联系地址和到期提醒。人工实测一次权属、续期、域名变更与旧分享地址接续。 |
| 付款与退款由谁负责 | 代码已提供可选 Stripe 托管收银台和通知核验。实际收款由经营方开通合规商户，明确开票、退款、争议及对账负责人，并核验真实商户接入及生产通知。 |

百年保存仍是运营目标。正式承诺需要实际经营方落实资金、收费合同、受托主体、删除周期和接续责任，并将承诺范围、履约证据与家庭获取资料的方法持续公开。
