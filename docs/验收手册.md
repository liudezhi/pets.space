# 栖光谷 · 验收手册

想先看景，可在现代浏览器中打开免安装游览 HTML。要验收建园、探访与赠礼，可解压完整验收包，按《从这里开始》启动；也可按 [README](../README.md) 从源代码启动本地沙盒。准备一张可用于测试的猫狗照片。以下步骤可以使用虚构的名字与留言。准备两个彼此独立的浏览器配置，一个模拟主人，一个模拟来访亲友。测试交接时再用第三个配置开通另一位园主。所有浏览器应访问同一套服务和数据目录。

## 1. 从草坡走到石前

- **入口与地标**　从「园区地图」选择「入口望树」，进入 3D，沿草径走到河湾纪念石，再过桥去「树下回望」。从树下回看，桥和白桦仍能指明来路。「听风山庭」是第四处可直达地标。退出漫游后可以继续读相册。
- **每区六块纪念地**　在已公开若干测试花园后进入漫游，打开「沿路花园」，选择一处纪念地并点击「到石前」。靠近石碑后应能访问对应纪念册，照片与名字和公开档案一致。每区最多六块，区间复用步道几何与地块位置。要验证翻区，准备足够多且跨区的公开测试档案，然后点「上一区」或「下一区」。撤回公开后重新进入或等地图刷新，原位置撤下，其他家庭的位置保持稳定。仅有示例档案时可看到麦子。
- **时光与天气**　在「时光与天气」选择春季日出、秋季日落、冬季星夜，再分别预览雨和雷雨。观察太阳、月亮或星空、草木、降水与积雪的变化。分别关闭雷鸣、闪光和动态效果。园区时间使用北京时间，正常天气按六小时段计算；预览只改变本机 3D，图片取景保持原构图。
- **可达性**　在手机视口操作方向键和地标直达，再在禁用 WebGL 的浏览器进入漫游。应显示回退提示，地图、图片和纪念册仍可打开。真机另外记录设备、系统、浏览器、首屏耗时、操作流畅度和发热情况。

## 2. 主人与亲友的两条路径

| 操作 | 应观察到 |
| --- | --- |
| 主人用沙盒邀请码创建基础订单，点「稍后再看」后刷新 | 在「我的花园」的「本浏览器的订单」继续原订单。完成模拟付款后保存恢复码。 |
| 选河湾或桦坡，上传照片，勾选「同时私密保存原始照片」，私密预览后保存 | 主人能读到回忆、照片与所选地点。以亲友身份直接打开私密地址，无法读取纪念档案或图片。 |
| 主人公开花园并发出链接 | 亲友直接到达这只宠物的纪念册。测试跨设备分享时，链接须使用双方可访问的服务器地址。 |
| 亲友点「免费献花」；主人刷新 | 无需登录或购买资格即可放下一束雏菊，两侧看到更新后的花束数。主人关闭收花后，亲友重新打开，送花入口收起。 |
| 亲友在「更多纪念礼物」选择白百合或陶瓷花瓶 | 标价分别为 ¥6 与 ¥18。沙盒采用模拟付款；百合展示七天，花瓶长期陈列。礼物订单和园主资格各自独立，纪念册保留探访记录。 |
| 主人或亲友点「到花园看看」 | 在对应 3D 纪念地看到宠物照片和可展示的礼物，退出后可以回到这座花园的纪念册。 |
| 主人升级「家庭庭院」并将自家两处纪念地加入 | 沙盒庭院示例价 ¥88。可在成员之间探访，点「走进家庭庭院」进入山庭。亲友只看得到主动公开的成员。 |

## 3. 寄语、相册和家人接管

1. 在「许愿树寄语」中为选定的宠物写两条留言。勾选一条「当花园公开时展示这条寄语」。亲友可读公开的那一条；主人将整座园转私密后，再次打开许愿墙，公开条目也会撤下。
2. 在「家庭相册」加入一张原始照片。每园最多六张原件，每张不超过 8 MiB。主人选择「允许访客查看」后，公开花园中的亲友可读展示版。撤回该照片的公开授权，原分享图地址应失效。主人仍可以导出原件。
3. 点「导出离线纪念册」，将下载的 HTML 复制到断网设备，用浏览器打开。核对园址、看景方向、固定风景图、宠物照片、姓名、纪念文字、寄语和献花记录。在离线页面保存原图与机器可读档案，计算导出原图的 SHA-256，与档案中的 `photos[].sha256` 比较。此文件含私密内容，请交由获授权家人保管。
4. 在新浏览器使用原园主恢复码。新会话应能查看原有花园，并收到新的恢复码；已兑换的旧码失效。把「换设备回访」与「转交所有权」分别测试。
5. 家人在自己的园主身份中打开页脚「家庭交接」，提供自己的接收编号。原主人在「交给家人维护」生成指定接收人的交接码。有效期七天，原主人可撤回。由家人接收后，花园转为私密，档案和私人寄语归新主人管理；原主人失去管理权。
6. 如需测试删除，另建专用的虚构花园，先导出纪念册，再输入完整宠物名字并确认。验证当前服务的档案、相册和寄语已清除。备份的保留与删除周期按运营约定执行。

## 4. 付款与恢复的验收边界

默认沙盒使用站内模拟结算。可选 Stripe 托管模式由服务端选定。真实商户测试需具备商户测试凭据、可回调的 HTTPS 域名和对应 webhook。完整配置见[运行与百年保存](运行与百年保存.md)。

- **订单未确认**　成功返回链接只会触发订单查询。服务端收到有效支付通知后才发放权益。网络中断或取消时，在同一浏览器查询原订单；已付款但暂未显示确认时，先核对状态。
- **回款后不能履约**　例如亲友打开收银台后主人关闭收礼。订单应转为人工核对，不放置礼物。按原订单号联系运营方处理对账、退款。
- **自动验证**　在仓库根目录运行 `npm test`。测试含独立数据库、模拟购买者、签名通知测试桩、重复通知、过期会话、隐私撤回、档案迁移、离线原件校验、备份恢复与时间计算。运行 `npm run build` 再测试构建版。

## 5. 已执行与待外部验证

本地生产构建用 Chromium 桌面 1366 × 768、触屏模拟 390 × 844 和独立会话进行了园主、亲友及家人流程验证。手机视口的独立支付桩覆盖了测试与正式模式文案、托管页面跳转与取消、延迟确认、领取权益、失败重试和人工核对。离线纪念册在新建离线上下文中渲染并验证无 HTTP 依赖，导出 JPEG 与原件摘要一致。以真实接口运行的归档测试另外验证了已过期礼物的保存。

公共园区也以七份虚构档案实测，首区六个位置与第二区可前后切换，手机模拟中能从石碑进入正确的纪念册并免费献花。桌面验证了从入口按键步行到第六处纪念地，以及用鼠标点选碑面进入正确档案。撤回公开后，原碑入口也会停止访问。

本轮尚未连接真实商户或进行真实扣款，也未公开部署。真机 Safari/Android、跨公网分享、长期运营资金、合同、持续异地备份和值班均须由对应责任人实际核验。体验记录可写下版本、设备、步骤、预期、实际结果和证据，便于下次复测。[验收记录与截图](../design-qa.md)
